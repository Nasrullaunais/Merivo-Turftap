# Decision log

One file per decision that is hard to undo, would surprise a newcomer, and had real alternatives. Smaller choices live in `AGENTS.md` or the architecture docs.

| # | Decision | Status |
|---|---|---|
| [0001](0001-modular-monolith.md) | One app split into modules, not separate services | accepted |
| [0002](0002-bun-hono-backend.md) | Backend runs on Bun with Hono | accepted |
| [0003](0003-third-parties-behind-adapters.md) | Every outside service sits behind our own interface | accepted |
| [0004](0004-resource-based-api.md) | The API is resource-based, with five routes per resource | accepted |
| [0005](0005-tenant-id-per-row.md) | Tenants share tables, separated by a tenant id on every row | accepted |
| [0006](0006-n8n-receives-chats.md) | n8n receives WhatsApp chats; the backend sends notifications | accepted |
| [0007](0007-bank-transfer-with-ai-check.md) | Version 1 takes payment by bank transfer, checked by staff with AI help | accepted |
| [0008](0008-phone-login-for-everyone.md) | Everyone signs in with a phone number and a WhatsApp code | accepted |
| [0009](0009-drizzle-migrations.md) | Migrations are generated by drizzle-kit and applied by Drizzle's own migrator | accepted |
| [0010](0010-login-codes-fall-back-to-sms.md) | Login codes go by WhatsApp first, then SMS | accepted |
| [0011](0011-staff-limited-to-venues.md) | Staff can be limited to some venues; roles stay fixed in code | accepted |
| [0012](0012-files-in-cloudflare-r2.md) | Files are kept in Cloudflare R2 | accepted |
